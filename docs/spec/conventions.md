### Cosmetric — Conventions for Code Generation (KISS)

Источник правды — `vision.md`. Здесь только практические нормы для генерации кода. При несовпадениях следуй `vision.md` и не дублируй его содержимое.

### Общие принципы
- **KISS и MVP**: самый простой рабочий вариант, минимум зависимостей и сервисов. Не добавляй брокеры/кэш/ES на MVP; используй Postgres и его FTS. Детали — в `vision.md`.
- **API‑first**: контракт (OpenAPI/Swagger) — первичен. Все DTO строгие, с валидацией и трансформацией. Документация всегда актуальна.
- **Монолит**: Backend — NestJS (Fastify) Controller → Service → Repository (Prisma). Frontend — Next.js App Router + SSR/SSG.
- **Совместные типы**: общие DTO/типы — из `packages/shared`; не дублируй их в приложениях.

### Архитектурные границы
- **Backend**:
  - Контроллеры: только прием/валидация/маппинг. Бизнес‑логика — в сервисах. Доступ к БД — в репозиториях (Prisma).
  - Валидация: `class-validator`/`class-transformer` + Pipes. Пагинация limit/offset с безопасными пределами.
  - Ошибки: единый фильтр ошибок, корректные HTTP‑коды и форматы ответов.
  - Конфиг: только ENV, строгая валидация схемой, fail‑fast при ошибках.
  - Логи: структурные (pino), `requestId`, маскирование чувствительных полей.
  - Аутентификация: JWT (access+refresh) в HttpOnly cookie; SSR‑совместимо.
  - Фича‑флаги/A‑B: хранятся в БД, загружаются при старте, оценка на сервере; фоллбек на ENV при недоступности БД.
  - Поиск: только Postgres FTS и индексы; никаких внешних поисковых систем на MVP.
- **Frontend**:
  - SSR/SSG по маршрутам из `vision.md`. Доступ к API с учетом cookie при SSR.
  - UI: headless‑подход, Tailwind. Изображения — `next/image`, хранение оригиналов, on‑the‑fly оптимизация.
  - Переменные окружения: только `NEXT_PUBLIC_*` публично; секреты остаются на сервере.

### Качество и жизненный цикл
- **Линт/формат**: ESLint + Prettier обязательны. Исправляй предупреждения/ошибки до коммита.
- **Тесты**: при добавлении доменной логики — unit‑тесты (Jest), для критических флоу — минимальные e2e (supertest). См. приоритеты в `vision.md`.
- **CI Quality Gates**: линт + unit‑тесты должны проходить; без зелёного CI не мёржим/не деплоим.
- **PR‑процесс**: маленькие инкременты, минимум 1 approve, защищённые ветки, ветвление как в `vision.md`.

### Производительность и устойчивость
- Следуй бюджетам из `vision.md` (например, P95 поиска ≤ 500 мс). Пагинация всегда серверная. Избегай N+1, используй индексы и продуманные запросы.
- Не логируй тела запросов/ответов по умолчанию; маскируй секреты.

### Стиль кода (TypeScript)
- Явные типы на публичных API/границах модулей. Не используй `any` без необходимости; предпочитай `unknown` и узкие типы.
- Управление потоком: ранние возвраты и проверка ошибок, избегай глубокой вложенности. Не глуши исключения.
- Комментарии — только «почему», не «что». Избегай TODO — реализуй сразу.
- Именование: говорящие имена для переменных/функций. Для анонимных коллбэков методов массивов (map/forEach/filter/reduce) соблюдай правило:
  - Если функция атомарная — параметр как первая буква подходящего слова: `demands.map(d => ...)`.
  - Или `x`, когда элемент очевиден из контекста: `publishers.map(x => x.toString())`.
  - Эти сокращения — только для аргументов анонимных функций. Для обычных переменных и параметров именованных функций — полные осмысленные имена.

### Генерация API и данных
- DTO — единственный источник типов для входа/выхода контроллеров. Синхронизируй декораторы/схемы со Swagger.
- Миграции и сиды — через Prisma, детерминированны. Любое изменение схемы сопровождается миграцией и seed‑обновлением при необходимости.

### Недопустимо на MVP
- Вводить новые инфраструктурные компоненты (брокеры, кэши, внешние поиски) без явного апдейта `vision.md`.
- Дублировать типы/DTO в разных пакетах. Писать бизнес‑логику в контроллерах/Prisma‑слое.
- Хардкодить секреты/конфиги вне ENV. Логировать чувствительные данные.

### Как принимать решения
- Если есть неоднозначность — выбирай самый простой вариант, совместимый с `vision.md`, и оставляй короткий комментарий «почему так». При необходимости — обновляй `vision.md`.
