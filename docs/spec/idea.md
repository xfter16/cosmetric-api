## Cosmetric — идея веб‑приложения для поиска косметики по составу

### Как я понимаю задачу
Цель — дать пользователю быстрый и интуитивный поиск косметики, где главным критерием является состав (INCI), а не маркетинговые описания. Пользователь должен:
- быстро находить товары по категориям (шампуни, кремы, сыворотки и т. п.);
- гибко фильтровать по ингредиентам: исключать нежелательные, требовать обязательные, задавать желательные;
- видеть удобные карточки товаров: описание, полный состав, подсветка ключевых компонентов, ссылки на магазины/маркетплейсы;
- просматривать подробные страницы ингредиентов с описанием, рекомендациями и рейтингами (в т. ч. «рейтинг опасности»).

### Почему это важно
- **Осознанный выбор:** пользователи всё чаще выбирают по составу, учитывая аллергенность, комедогенность, этичность и т. п.
- **Скорость и простота:** большинство решений перегружены; нужен интерфейс «в 2–3 действия» до результата.
- **Доверие:** прозрачность состава и обоснованные рекомендации повышают лояльность и возврат пользователей.

### Правильное решение (кратко)
Веб‑приложение с быстрым индексным поиском по базе товаров и ингредиентов, с удобными фильтрами на уровне состава и понятными карточками результатов. Поиск должен работать за доли секунд, а фильтры — быть выразительными (обязательные/исключённые/желательные ингредиенты) и сохраняемыми.

### Основные сценарии
1) **Поиск по категориям**
   - Старт с выбора категории (или через строку поиска с подсказками категорий).
   - Быстрые пресеты (например, «для чувствительной кожи», «без отдушек», «веган»).

2) **Фильтры по ингредиентам**
   - Обязательные: товары ДОЛЖНЫ содержать все перечисленные ингредиенты.
   - Исключить: товары НЕ ДОЛЖНЫ содержать ни один из перечисленных.
   - Желательные/нежелательные: влияют на ранжирование (выше/ниже в выдаче), но не отбрасывают полностью.
   - Доп. параметры: группы ингредиентов (SPF‑фильтры, ПАВы, отдушки), аллергены, комедогенность, pH‑совместимость (где применимо).

3) **Результаты поиска и карточка товара**
   - Список результатов: быстрый, с пагинацией/виртуализацией, фасеты по брендам/цене/подкатегориям.
   - Карточка товара: краткое описание, фото, бейджи (например, «без отдушек», «веган»), ссылки на магазины/маркетплейсы.
   - Состав (INCI): полный список с расшифровками и ролями (растворитель, консервант, УФ‑фильтр и т. п.), подсветка совпадений с фильтрами.

4) **Страница ингредиента**
   - Описание: что это, для чего используется, источники.
   - Рекомендации: кому подходит/не подходит, совместимость с другими компонентами.
   - Рейтинги: опасность/раздражающий потенциал, комедогенность, уровень доказательности.
   - Дополнительно: допустимые концентрации, ссылки на авторитетные источники.

### Требования к UX
- Минимум кликов до результата: поле поиска + блок фильтров видим «сразу».
- Сохранённые наборы фильтров («мои правила состава»), быстрые переключатели.
- Понятные индикаторы соответствия: почему товар показан, какие условия выполнены/нарушены.
- Мобильная оптимизация и высокая читабельность состава.

### Требования к производительности
- Индексированный поиск: обратный индекс по ингредиентам, фасеты по категориям/брендам.
- Быстрые логические операции: пересечения для «обязательных», вычитания для «исключить», скоринг для «желательных».
- Асимметричный кеш: популярные запросы/наборы фильтров, CDN для статики и изображений.
- Дебаунс запросов, инкрементальные обновления, серверная пагинация/виртуализация списка.

### Данные и нормализация состава
- Источники: открытые каталоги, страницы брендов, маркетплейсы (при соблюдении прав), пользовательские карточки.
- Нормализация INCI: синонимы, орфографические вариации, объединение в группы.
- Обогащение: роли ингредиентов, совместимости, возможные концентрации, ссылки на исследования.

### MVP (первый релиз)
- Поиск по 3–5 основным категориям.
- Фильтры: обязательные, исключить, желательные (базовый вариант).
- Карточка товара: описание, фото, состав с подсветкой совпадений, 2–3 внешние ссылки на покупку.
- Страница ингредиента: описание + базовый рейтинг опасности и рекомендации.

### Метрики успеха
- Время ответа поиска P95 < 300–500 мс.
- CTR по товарам из выдачи, сохранения фильтров, возвраты пользователей.
- Доля карточек с полным и нормализованным составом.

### Основные риски и ответы
- Неполные/шумные составы: нормализация, краудсорс‑поправки, доверенные источники.
- Спорность «рейтинга опасности»: прозрачная методика, ссылки на источники, дисклеймеры.
- Поддержка скорости на объёмах: индексирование, кеш, фасеты, профилирование узких мест.

### Следующие шаги
1. Спецификация модели данных: товар, ингредиент, связь «товар‑ингредиент» с ролями.
2. Прототип поиска: индекс по ингредиентам (+ логика обязательных/исключений/желательных).
3. Импорт небольшой эталонной базы (1000–5000 товаров) и нормализация INCI.
4. UI: быстрые фильтры, список результатов, карточка товара, страница ингредиента.
5. Метрики и журнал поиска для оптимизации релевантности.


### Система аккаунтов и роли
- Типы аккаунтов:
  - Представитель производителя: верификация бренда, ведение карточек своих товаров, предложение правок состава, ответы на отзывы, бейдж «официальный представитель».
  - Модератор: обработка жалоб, премодерация спорного контента, правки категорий/тегов, меры против нарушений (скрытие, бан, теневой бан).
  - Администратор: управление ролями и политиками, источниками данных, правилами ранжирования, финальные решения по апелляциям.
  - Пользователь: поиск, списки, отзывы/оценки, комментарии, жалобы на контент.
  - Пользователь‑эксперт: подтверждённые компетенции (например, косметолог), экспертные рецензии, повышенный вес оценок, бейдж «Эксперт».
- Профиль: бейджи, уровень доверия, вклад (количество рецензий/полезных отметок), настройки приватности.
- Авторизация: email + пароль, OAuth (Google/Apple), 2FA (позже).

### Верификация и доверие
- Эксперт: заявка с документами/ссылками, ручная проверка модератором/админом, периодическая ревалидация.
- Представитель производителя: подтверждение домена/почты бренда и юридических документов.
- Уровни доверия: новый → подтверждённый → эксперт → представитель; накапливаемый trust score через полезность и историю без нарушений.

### Контент: комментарии, отзывы, рецензии
- Типы:
  - Комментарий: короткая реплика без оценки.
  - Отзыв: субъективная оценка товара (звёзды) + краткое объяснение.
  - Рецензия: структурированный разбор состава с аргументацией и ссылками на источники.
- Значимость: рецензия > отзыв > комментарий; эксперты и представители имеют больший вес, чем обычные пользователи.
- Механика полезности: «полезно/неполезно», сортировка по полезности и свежести, фильтры «только эксперты»/«только подтверждённые».

### Модель веса и ранжирования
- Вес автора: w_author = f(роль, уровень доверия).
- Вес контента: w_type (рецензия > отзыв > комментарий).
- Итоговый вклад в рейтинг товара: weighted_rating = Σ(score_i × w_author_i × w_type_i) ÷ Σ(w_author_i × w_type_i).
- Маркировка конфликтов интересов: контент представителя производителя визуально помечается; его вклад может ограничиваться в агрегированном рейтинге.

### Модерация
- Жалобы: спам, токсичность/оскорбления, конфликт интересов, недостоверные утверждения.
- Инструменты: скрыть/удалить, запрос правок, пометки причин, эскалация админу, временные ограничения.
- Потоки:
  - Премодерация: обязательна для новых/низкого доверия и контента с внешними ссылками.
  - Постмодерация: для остального контента с работающей системой жалоб и автоматическим приоритетом очереди.
- Автоматизация: антиспам, детекция токсичности, ограничение частоты публикаций, дедупликация, авто‑архив старых споров.
- Апелляции: прозрачная процедура и сроки рассмотрения.

### MVP для аккаунтов и модерации
- Роли: пользователь, модератор, админ; заявки на «Эксперт» и «Представитель производителя» (ручная проверка).
- Публикация комментариев и отзывов; рецензии как длинная форма (без сложной структуры на старте).
- Простая шкала весов по умолчанию: эксперт = 3, подтверждённый = 1.5, пользователь = 1, новый = 0.5; тип контента: рецензия = 2, отзыв = 1, комментарий = 0.5.
- Очередь жалоб с действиями модератора: скрыть/удалить/бан, журнал решений.
- Взвешенный рейтинг товара и сортировка отзывов по полезности и весу автора.
